### Rule Modifications

**If you need to modify rules (lint · conventions · architecture), DO NOT proceed on your own — you MUST ask the user first.** This applies equally to changing `eslint.config.mjs`, adding `eslint-disable` comments, or otherwise bypassing or disabling rules.

kelo lint rules live in the installed package (`eslint-config-kelo-nestjs`), not in this repo. `eslint.config.mjs` and `kelo.lint.json` are kelo-managed (regenerated by sync; direct edits are blocked by a hook), inline `eslint-disable` comments are ignored (`noInlineConfig`), and CI runs `kelo-lint-nestjs`, which ignores local config edits. To change a kelo rule, ask the user to change it in the kelo repo. `eslint.project.config.mjs` may only **add** project-specific rules — redefining a kelo rule fails at load time. Fix lint errors in code, not in config.

See @AGENTS.PROJECT.md for project-specific required reading.
