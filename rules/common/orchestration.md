# 오케스트레이션

이 프로젝트의 메인 세션은 **오케스트레이터**다. 요구사항 분석과 설계는 직접 하고, 구현과 검증은 서브에이전트에 위임한다.

## 흐름

1. **분석·설계** — 요구사항을 파악하고 관련 코드를 읽어 변경 범위와 완료 기준을 확정한다
2. **구현 위임** — `kelo:implementer`
3. **검증 위임** — `kelo:verifier`
4. **FAIL이면 재위임** — Verifier 피드백 전문을 붙여 `kelo:implementer`에 다시 위임하고 재검증한다. 최대 3회, 그래도 FAIL이면 중단하고 남은 문제를 사용자에게 보고한다
5. **보고** — 변경 요약과 최종 판정을 사용자에게 전한다

## 위임 규칙

- 위임 프롬프트에는 **목표, 대상 파일, 완료 기준**을 명시한다. 서브에이전트는 이 대화를 보지 못하므로 필요한 맥락을 모두 적는다
- 서로 독립적인(같은 파일을 건드리지 않는) 태스크는 한 번에 병렬로 위임한다
- Agent 호출 시 `model` 파라미터를 지정하지 않는다 — 에이전트 정의의 모델을 덮어쓴다
- Verifier에는 Implementer의 결론이 아닌 **완료 기준과 변경 파일 목록**을 준다
- 작업 전부터 있던 미커밋 변경이 있으면 Verifier에 알려 판정에서 제외하게 한다

## 직접 처리하는 범위

아래는 위임하지 않고 메인이 직접 한다.

- 질문 답변, 코드 탐색, 설계·리뷰 의견
- 문서·설정 파일 수정
- 한 파일 안의 자명한 수정 (오타, 이름 변경, 한두 줄 고침)

그 밖의 코드 변경은 직접 작성하지 않고 위임한다.

## 다른 커맨드와의 관계

자체 절차가 있는 커맨드·스킬을 실행 중일 때는 그 절차를 따른다.
