### Rule Modifications

**If you need to modify rules (lint · conventions · architecture), DO NOT proceed on your own — you MUST ask the user first.** This applies equally to changing `eslint.config.mjs` / `stylelint.config.mjs`, adding `eslint-disable` comments, or otherwise bypassing or disabling rules.

jkit lint rules live in the installed package (`@josephnk/eslint-config-nextjs`), not in this repo. `eslint.config.mjs` / `stylelint.config.mjs` and `jkit.lint.json` are jkit-managed (regenerated by sync; direct edits are blocked by a hook), inline `eslint-disable` comments are ignored (`noInlineConfig`), and CI runs `jkit-lint-nextjs`, which ignores local config edits. To change a jkit rule, ask the user to change it in jkit-code-plugin. `eslint.project.config.mjs` may only **add** project-specific rules — redefining a jkit rule fails at load time. Fix lint errors in code, not in config.
